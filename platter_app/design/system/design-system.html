Cerulean & Apricot · v1.0

Design system

Every component here is built from semantic tokens, never raw hex. That's what makes the next palette change a one-file edit instead of a rebuild — which we've now proven once.

Semantic tokens

--accent-*Selection, focus, active tool. Apricot. Never decorative, never a brand flourish — if something is apricot, the user is acting on it.
--info-*Structure, links, primary data series. Cerulean.
--success-*Confirmed, complete, high confidence. Sea green.
--danger-*Bond, mandatory, overdue, low confidence, destructive. Grapefruit.
--bg-shell-*Dark chassis: nav, sidebar, command bar.
--bg-surface-*Light work surfaces: tables, sheets, cards, planroom.

Each intent has four values, and they are not interchangeable. fill is the bright hue — backgrounds only. line is one step darker for hairlines. text is the dark shade, the only one legible as type on floral white. wash is the tinted background. Using fill as text is the single most likely way to break this system.

Elevation & motion

Shadows are warm-tinted, never neutral grey — a cool shadow on floral white reads as dirt.

Motion: 120ms for color and state, 180ms for movement and reveal, 240ms for layout shifts. Easing is cubic-bezier(.2,.7,.3,1) for anything entering. All durations collapse to 0 under reduced-motion.

Buttons

Labels state the outcome. "Save changes," never "Submit." An action keeps its verb through the whole flow.

The command bar reads from a registry, not a hardcoded list. Every action in the app registers {id, label, keywords, scope, run()}, and context menus and keyboard shortcuts read from the same source. On iPad the registry opens as a sheet from a floating glyph instead.

Four parts, always in this order: confidence dot, the value, the source citation, the action. The citation is a live link — clicking it opens the document at that page with the region highlighted. That gesture is the product's trust mechanism, so it's a component, not a screen.

Accessibility floor

RequirementRule
Body text contrast4.5:1 minimum. Only *-text shades on floral white — never a *-fill.
FocusNever removed. 2px apricot ring, 2px offset, visible on both shell and surface.
Touch targets44px minimum on iPad. Card band buttons and .btn--lg meet it; .btn--sm is desktop-only.
Color aloneNever the sole signal. Confidence has a dot and a number. Flags have a chip and a label.
MotionAll durations collapse to 0 under prefers-reduced-motion.
DaylightWork surfaces are light by default — this gets used on a jobsite iPad in sun.

How to extend this. Add a component only when a pattern appears three times. Build it from semantic tokens exclusively — if you find yourself needing a raw hex, the token set is missing something, and that's the thing to fix. Every new component needs its hover, focus, disabled, loading, empty and error states defined before it ships, because the ones that get skipped are always the ones that break.
