3.3

Scope tool — workflow chooser

One job: let the fastest path win without forcing it. Three ways in, one worksheet out.

Deep AI parse

Reads every uploaded spec and drawing, proposes a full package list with budget estimates and schedule flags for review.

Best for · full spec set already uploaded

Spec-driven

Browse the spec index yourself, pick sections, and let Platter propose packages from what you selected — a middle path.

Best for · known scope, partial spec

Manual

Work side-by-side with the drawing set and build the worksheet by hand, package by package, line by line.

Best for · negotiated work, no formal spec

All three write to the same scope_line_item table (R-01) — the choice only changes how the first draft gets there. Switching flows mid-package is always available; nothing is a one-way door.

  1. 1Deep parse is pre-selected because it's priority #1 (D-07) and the fastest path when the documents support it — but selection is a click away from any card, never a wizard you're locked into.
  2. 2"Best for" replaces a recommendation engine. Plain criteria the estimator can judge themselves beats a black-box suggestion for a decision this consequential.

What Batch 3 commits us to. Kind badges (inclusion/exclusion/alternate/allowance/unit price/clarification/VA option) become the fixed vocabulary the bid tab and budget both have to render. The provenance row now has a third shape — parsed line items alongside parsed project fields and parsed sub quotes — same four parts every time. And the exclusion cross-reference (line → package) is a new obligation: Batch 5's bid tab needs to resolve "where did this excluded scope end up" without the estimator hunting for it.
